## Scope

LOOMERA_CANONICAL_PASSWORD_LOGIN defaults false. On opt-in the existing Django ModelBackend uses CustomUserManager's synchronous/asynchronous natural-key lookup against both the generated canonical identity and its exact expected stored username. Iranian inputs map to the original 09 username, including common aliases and Persian/Arabic digits. No raw fallback or aliasing of tombstones. Active status, password hashing, permissions and platform admin restrictions still use existing authentication. Foreign explicit +E.164 identities must match pinned phonenumbers 9.0.44 geographic MOBILE or FIXED_LINE_OR_MOBILE metadata; no guessed foreign national number, extensions, nongeographic codes or landlines. Number plan metadata does not prove number ownership. Iranian legacy numbering remains shape-based for continuity. Login page preserves plus/digits in the opt-in mode; Iranian signup/reset and mobile OTP API normalize to the same existing Iranian namespace. Foreign OTP remains unsupported and is denied before web cooldown/OTP creation, including disabled/simulated SMS. No new unauthenticated API password endpoint. The existing authenticated web session can use the API's session-based status/me endpoints.

Foreign onboarding is deliberately operator-only, not public signup: provision_verified_foreign_customer requires enabled flag, an interactive private terminal, explicit verified-ownership and non-SMS-recovery acknowledgments, canonical mobile, validated password and confirmation. Password and number are not CLI args or echoed in output. It atomically creates a nonstaff, nonsuperuser active customer with SMS/WhatsApp preferences disabled and refuses duplicates. The operator must independently verify number ownership and arrange a secure credential handoff/recovery; no proof of ownership is inferred from the library or operator flag. No role escalation, public foreign password reset or foreign OTP is offered. Foreign mobile is read-only in Django admin; foreign role onboarding and automated recovery remain release-gated. When disabled the manager denies explicit plus-form password identities; existing sessions are not revoked automatically, so disable/rollback needs session drain/revocation and data review. Package A reverse migration refuses foreign usernames.
